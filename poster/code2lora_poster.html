Code2LoRA

Repository-Aware Adapter Generation via Composable Hypernetworks

EMNLP 2025

🎯

Motivation

❌
Context Window Limits: RAG and ICL are bounded by context length, adding latency per query
❌
Per-Repo Training: Traditional LoRA requires retraining for each new repository
❌
Linear Cost: Inference cost scales with context size
✓
Our Solution: Distill repository knowledge into adapter parameters via hypernetworks — zero tokens at inference
💡

Key Contributions

1
Code2LoRA: First hypernetwork for generating repo-conditioned LoRA adapters for code LLMs
2
Two architectures: Direct-projection & shared-basis variants with 8.5× parameter efficiency
3
RepoPeftBench: New benchmark of 560 Python repositories with 73K assertion tasks
4
+18pp over pretrained: Substantial gains on cross-repo evaluation
⚡

Why Code2LoRA?

🔬 Key Findings
✓ +18.1pp over pretrained on cross-repo evaluation
✓ Context-based methods (RAG, ICL) underperform — retrieval noise hurts
✓ Parametric adaptation outperforms context injection
✓ Shared-basis achieves comparable performance with 8.5× fewer parameters
💭 Insight

Repository knowledge should be internalized into model parameters rather than injected as context. For assertion completion, targets depend on local context — retrieved chunks consume budget without direct benefit.

Single forward pass: <10ms adapter generation per repository, zero inference token overhead.
